# M9 — общий ingest сервис: настоящий S3 и несколько локальных исполнителей

M9 расширяет M8, не создавая второй парсер или вторую базу каталога. Вход — **утверждённый** `selected-work-v1` с подготовленными HTML-снимками. Сетевых запросов к Literotica, автоматического импорта в Эриду и перевода нет.

## Поток

`POST /v1/jobs → SQLite WAL → worker slots (1–8) → per-job flock → M5 RAW/parsed ledger → M4 immutable S3 → verified current.json → handoff`.

Запись в S3 через существующие `S3ObjectSink`, `StreamingWorkPublisher`, журнал multipart и CAS. Worker не решает, какие сайты обходить, не меняет права и не подтверждает импорт в Эриду.

## Несколько исполнителей

- Общая для state-директории конфигурация числа слотов фиксируется в SQLite (`ingest_settings.worker_slots`). Нельзя случайно запустить два процесса с несовместимым лимитом.
- `worker-slots/slot-N.lock`: POSIX flock ограничивает общее число одновременно выполняющих работу процессов/потоков на **одном хосте**.
- `job-locks/<job_id>.lock`: в каждый момент конкретную книгу обрабатывает не больше одного исполнителя. Разные книги выполняются параллельно.
- Заброшенные `RUNNING` не обнуляются глобально: новый исполнитель восстанавливает **только** задание, на которое он получил файловый замок. Устаревший SQLite `lease_token` не может подтвердить результат.
- Очередь в SQLite, без Redis/Kafka и без многосерверного координатора. На NFS/SMB и между разными серверами гарантии flock **не заявляются**.
- Максимум 8 исполнителей на один локальный state каталог, для общей производительности и S3 нагрузки. Можно снижать нагрузку перезапуском сервиса с согласованной конфигурацией; динамическое изменение лимита требует отдельной процедуры миграции.

## Пример оператора

```sh
cd experiments/unified-ingest-m5
python -m pip install -e '.[test]'
export INGEST_API_TOKEN="$(python -c 'import secrets; print(secrets.token_urlsafe(36))')"
export AWS_ACCESS_KEY_ID='...'
export AWS_SECRET_ACCESS_KEY='...'
export AWS_DEFAULT_REGION=us-east-1
python -m discovery_lab.service_cli serve \
  --state /srv/ingest/state --approved-root /srv/ingest/approved \
  --max-workers 2 --port 8765 \
  --s3-bucket approved-ingest --s3-endpoint https://s3.example.com \
  --s3-prefix ingest/
```

API только loopback, для использования извне нужен отдельный TLS-гейт. Токены и ключи не помещать в задания/репозиторий. `GET /v1/queue` доступен только с bearer-токеном, выдаёт численность QUEUED/RUNNING/COMPLETED/NEEDS_REVIEW/CANCELLED без персональных данных.

## Приёмка

1. Локально: `python -m unittest discover -s tests -p 'test_m[56789]*.py' -q`, ожидается 61 тест.
2. GitHub Actions M9: Docker MinIO с включённым versioning; API принимает две работы; два исполнителя обрабатывают разные книги; один RAW до начала имитирует сохранённый PUT с потерянным подтверждением SQL.
3. Обязателен SHA-256 readback для RAW и всех опубликованных файлов, проверка `current.json`, ровно одна версия повторённого RAW, 0 пропусков и `RUNNING=0`.
4. Тестирование против третьестороннего зеркала MinIO проводится только в одноразовом CI. Для production требуются верифицированный образ, закреплённый SHA256 digest/SBOM, подлинные TLS/S3-параметры.

## Не доказано

- Гарантии распределения между несколькими машинами, предел RSS для длинных глав, retry при 429/503, удалённый сервер авторизации, возобновление незавершённого multipart для крупной главы на настоящем MinIO именно в M9.
- Реальная полнота Literotica и авторские права, допуск robots/ToS, совместимость с актуальным DOM — без подтверждённых разрешённых образцов это остаётся за пределами эксперимента.
- Отсутствие потерянных подтверждений при любом возможном сетевом разрыве: тест воспроизводит определённый сценарий, а не всю комбинацию сбоев.
