# Акула: публичное S3 + P2P — первый опыт

Отдельный исследовательский проект. Публичный S3 — **единственный постоянный источник** материалов; браузеры могут добровольно раздавать друг другу уже загруженные и проверенные части по WebRTC. Это **не** распределённое хранилище и **не** доработанная/проверенная функция основного приложения «Акула».

## Быстрый запуск на одном ПК

Нужны Python 3.11+ и современный браузер. npm, Docker, S3-ключи для локальной проверки **не нужны**.

```bash
python3 -m pip install -r requirements.txt
python3 server.py
```

Откройте **http://127.0.0.1:8765/** в двух вкладках браузера:

1. В первой поставьте галочку **«Разрешить отдавать другим мои проверенные части»** и нажмите **«Получить файл»**. Проверенные части (8 МиБ в примере) окажутся в памяти этой вкладки.
2. Откройте вторую вкладку, дождитесь сообщения об открытии прямого канала, нажмите **«Получить файл»**. В успешном случае она получит части от первой вкладки, а не из исходного хранилища.
3. Снимите галочку в первой вкладке. Откройте третью вкладку и скачайте файл — она должна взять всё из исходного HTTP-источника.
4. Нажмите **«Сохранить»** в любой вкладке. Полный SHA-256 сверяется до появления ссылки на сохранение.
5. Откройте **http://127.0.0.1:8765/stats** и сравните объём `origin_bytes` с общим размером загруженных файлов.

Локальный `/origin/demo.bin` имитирует **публичный S3 GET/Range**, но не использует настоящий облачный S3. Это принципиально честное разграничение.

## Как подключить настоящий публичный S3

Материал сначала должен быть опубликован вами в S3-совместимом бакете. Для первой версии используйте **неизменяемый URL точной версии объекта**, а не URL, содержимое которого переписывается на месте. Бакет должен разрешать HTTPS GET и запрос заголовка `Range`; для чтения из браузера также нужны соответствующие CORS-правила, в том числе разрешённый заголовок `Range` и доступ к ответному `Content-Range`.

Сохраните **точную опубликованную копию** файла на компьютере, затем создайте манифест контрольных сумм:

```bash
python3 create_manifest.py /path/to/public-file.bin \
  --source-url 'https://public-bucket.example.org/immutable/path/public-file.bin' \
  --chunk-size 262144 \
  --out manifest.json
python3 server.py
```

Локальная серверная часть раздаёт только интерфейс/каталог/сообщения согласования. Содержимое браузер забирает **непосредственно с публичного S3-адреса**, минуя сервер сигнализации. В манифесте нет и не должно быть секретных ключей доступа.

**Важно:** при неизменном содержимом, но ошибочном URL браузер откажет по SHA-256. Если содержимое объекта обновилось, нужно опубликовать новый манифест/ContentID и не смешивать рои.

## Структура

- `create_manifest.py` — потоковое вычисление SHA-256 файла и каждой части; фиксированный ContentID (хеш полного файла).
- `server.py` — небольшой WebSocket-сервер для поиска участников и пересылки SDP/ICE; веб-сервер интерфейса; **локальный** HTTP Range-источник для испытаний.
- `web/client.js` — WebRTC DataChannel, запрос части по номеру, проверка хешей, ограниченный кеш и очереди, переключение на HTTP.
- `web/index.html` — простой интерфейс и статистика.
- `tests/test_server.py` — проверки манифеста, диапазонов HTTP и WebSocket-поиска.
- `tests/test_e2e_simulated.js` — испытание протокола с **имитацией WebRTC** между несколькими независимыми клиентами; при этом реальные HTTP и WebSocket запросы проходят через сервер.

## Проверки

```bash
python3 -m pip install -r requirements-dev.txt
PYTHONPATH=. python3 -m pytest -q tests/test_server.py
# Во второй терминальной вкладке оставьте работающим python3 server.py,
# затем:
node tests/test_e2e_simulated.js
```

Смоделированные сценарии (8 МиБ, 32 части): первый пользователь качает из HTTP; второй полностью из P2P; третий от **двух** раздающих одновременно; при изменении байтов одним недоверенным участником получатель отклоняет неверную часть и забирает её по HTTP; принудительный обрыв P2P в середине части тоже переключает получателя на HTTP; после отзыва согласия нового читателя обслуживает HTTP.

Это проверка логики программы, **не** доказательство реального соединения WebRTC в Chromium, Firefox, Safari или за NAT. В среде разработки Chromium имеет принудительную административную блокировку всех URL и политику, запрещающую прямой WebRTC/UDP; реальный двухбраузерный опыт поэтому здесь не запускался. Нужен независимый запуск на обычном ПК и затем ПК ↔ VPS через разные сети.

## Границы версии 0.1

- Раздача выключена, пока пользователь сам не поставит галочку. При прямом P2P соединении партнёры могут увидеть IP-адрес друг друга.
- Контрольные суммы каждого куска обязательны; допускается получение только конкретной опубликованной версии `content_id`. При ошибке проверка откажет в принятии данных.
- **Нет цифровой подписи манифеста.** Для испытания он считается доверенным, поскольку приходит с того же сайта, который открывает пользователь. Для внешней публичной раздачи следует добавить подписанный издателем манифест и закреплённый ключ проверки; обычный SHA-256 без доверенного списка хешей недостаточен против подмены источника.
- **Не реализовано надёжное фоновое хранение/раздача после закрытия браузера.** Кеш находится в ОЗУ вкладки, примерный предел 96 МиБ; при вытеснении данные можно заново получить из S3. Большие файлы потребуют OPFS/IndexedDB и потоковой записи.
- Участники передают небольшие сообщения WebRTC размером до 16 КиБ, сами части — по 256 КиБ. При обрыве передачи **текущая часть** загружается заново из HTTP, уже целиком проверенные части сохраняются; докачка с точного байта внутри части — следующий этап.
- Скорость отдачи ограничена на вкладку (выбор 1/4/8/16 МиБ/с, по умолчанию 8 МиБ/с); число уже открытых соединений в этом образце специально не ограничено, поэтому нужен последующий предел для продакшена.
- По умолчанию задан STUN, **TURN не настроен**. Если два участника не могут установить прямой канал через NAT, используются обычные HTTP Range запросы к S3. Для реальных внешних браузеров необходим HTTPS/WSS и настроенный домен.
- У сервера обнаружения ещё нет аутентификации, защиты от массовых подключений и полноценного учёта затрат. Это **локальная лаборатория**, а не сервис, который следует открывать в Интернет без доработки. Он принимает только один опубликованный `content_id`.
- Данные допускается раздавать только при наличии соответствующих прав. Публичное чтение S3 само по себе не разрешает публичную повторную раздачу.
- Реальная скорость и экономия S3 **не измерены**. Счётчик `origin_bytes` в локальном источнике измеряет байты, переданные его HTTP-сервером, а не счёт AWS S3.
