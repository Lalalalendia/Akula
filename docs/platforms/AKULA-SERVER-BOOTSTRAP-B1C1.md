# Akula B1c1 — existing QEMU signed Node, B1a root-pinned owner-CAS file commit, transient DynamicUser execution

**Status:** Experimental PR; NOT a production installer, release mechanism or durable VPS bootstrap. Root is trusted for the first single-owner self-hosted VPS. No external customer server, Desktop installation or Vault is changed.

## What is connected
Reuses the **existing** B1b2b Ubuntu QEMU test harness instead of cloning its image download/SSH provisioning/rollback infrastructure. Default B1b2b workflow behavior is unchanged. Only the new B1c1 workflow sets `AKULA_B1C1_VM_BRIDGE=SIGNED_ELF_TO_ROOT_CAS`; other values fail closed.

1. On the CI host, build actual `akula-node-lab`, strip debug symbols, produce existing canonical B1a Ed25519 manifest and signature using an ephemeral test key. Existing GPG-verified Ubuntu 24.04 image receives the **public release key via root-owned cloud-init** and proves its SHA-256 independently of the uploaded files. SSH uses the original strict host key pin.
2. Inside that guest, the already-provisioned original B1a verifier validates the uploaded v1 ELF and detached signature. The new opt-in Rust fixture parses the same canonical B1a manifest, checks root-owned public-key metadata, rechecks the **same key and Ed25519 signature** against actual ELF SHA-256/size and time, then pins the reverified root-owned staging inode with B1b3c `verify_root_staged`.
3. This fixture constructs a **synthetic test-only detached owner signature** for exactly that real release, plan/host/nonce and new floor, and exercises the previously accepted B1b4b0 root-owned CAS witness plus B1c0 `commit_first_signed_node_in_ci`. The resulting sole target is a root-owned mode 0555 `/run/akula-b1c0-one-shot-ci/target/node` copied from the held authenticated FD and fsynced after NOREPLACE rename.
4. The host independently compares the target SHA-256 with the exact originally signed host ELF. Since `/run` may have `noexec`, the disposable guest then copies those *already CAS-published, byte-verified* bytes to a single, previously absent, enrolled root-owned `/opt/akula-b1c1-committed-lab/node` (0555). It checks SHA-256 and byte equality again and fsyncs before launching. This **additional root-controlled copy is not yet a CAS-atomic /opt installer or crash-safe deployment**, and must not be counted as one. The service never executes from `/run`. The new temporary `akula-b1c1-cas-committed-node` systemd service executes **the byte-identical root-owned executable copy of the B1c0-committed file** under `DynamicUser=yes`, `NoNewPrivileges`, `ProtectSystem=strict`, localhost-only network and an inherited fixed credential wrapper. Assertions: health HTTP 200, anonymous note 401, authorized synthetic note 200, systemd restrictions, no remaining pending file.
5. Stop test service, remove only the explicitly enrolled disposable /run namespace; the existing B1b2b QEMU script then independently continues its signed bad-v2 rollback, installer SIGKILL, full guest reboot, forced QEMU SIGKILL with same qcow2, and recovery. That older crash test concerns its own /opt service, **not** the B1c1 /run file.

## Exact security nonclaims
- The owner-signed consent in this laboratory is **generated by the disposable root fixture**; this does **NOT** demonstrate a real owner's authorization UI, out-of-band signing, independent challenge issuance, or revocation.
- The root-owned same-guest CAS/Ed25519 signer is a cooperating-writer safety mechanism, not independent protection against malicious root, stolen key, forged clock, or full disk snapshot rollback.
- B1c1 writes under `/run`, which is **not a durable installation directory**; successful service launch does **not** prove boot persistence or upgrade crash recovery for the CAS-installed file. The existing B1b2b persistent /opt QEMU crash tests are related evidence, not a combined transaction proof.
- Node only serves synthetic read-only fixture data. There is no shell/install IPC opcode for Akula Desktop, no arbitrary filesystem target, and no production VPS connection.

**Next acceptance:** derive the durable single-owner /opt installer from the B1c0 fixed file commit, enforce one-use owner approval at the real activation boundary, add before/after rename and fsync fault injection, cold-boot recovery on same disk, and then an explicitly authorized first VPS test. Do not report B1c1 as working production installation.

## B1c1 mount/execute boundary correction

The first exact-head QEMU run authenticated the real signed ELF and CAS commit, but the transient DynamicUser service exited 126 with `Permission denied` when executing `/run/akula-b1c0-one-shot-ci/target/node`. Linux may mount `/run` with `noexec`, so production systems must not assume that staging paths are executable. This change uses a separate fixed root-owned `/opt` test directory, keeps the original signed ELF byte comparison, logs source mount options and requires a full systemd service/readback proof. No `noexec` remount, dynamic linker bypass or relaxation of systemd service restrictions is allowed. The Rust B1c0 CAS transaction still writes `/run`; a durable `/opt` transaction remains B1c2 work.
