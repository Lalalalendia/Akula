# AKULA B1c0 — fixed filesystem commit of signed Node bytes (disposable CI only)

Dependency: accepted B1b4b0 root-owned CAS lab [PR #499](https://github.com/Lalalalendia/Akula/pull/499). Separate from the read-only systemd witness [PR #501](https://github.com/Lalalalendia/Akula/pull/501). This is the **first limited root-owned FILE mutation** in this installer chain; it does **not** install a daemon, use SSH, enable service activation, or modify an installed Akula.

## Exact API and trust
- Opt-in Linux Rust feature `server-bootstrap-b1c0-fixed-node-lab`, not shipping in default Core or Windows. Function has **no pathname, command, shell, socket, owner/key material or executable override from an IPC request**.
- Only actual root on a disposable GitHub Actions Linux runner, after independent root-controlled enrollment at the single constant directory `/run/akula-b1c0-one-shot-ci`. Directory `0711`, root-owned `0600` marker, target `0755`, O_NOFOLLOW and strict metadata. Unknown/leftover/symlink `node` or `node.pending` refuses BEFORE consuming approval. No reset or cleanup of unexpected state.
- Root-held B1a signed ELF-like source bytes and unchanged inode plus time-valid signature are rechecked. The exact B1b1b owner detached approval is verified by the OS-owned witness against signed release, InstallId, approved plan, pinned SSH host and approved nonce. A **new** B1b1c CAS revision is fsynced; exact signed witness receipt is correlated again with root-pinned package and readback. A retry cannot commit another CAS or overwrite the installed file.
- AFTER CAS acceptance only, an O_EXCL file named `node.pending` is created at the one fixed target; exact bytes are streamed by `read_at` on the **already authenticated FD**, SHA-256 is checked again before commit, permissions become root-owned `0555`, file fsynced. Only exact `renameat(..., NOREPLACE)` publishes `node`; target directory is fsynced, and bytes SHA-256 are checked again after rename. No service is started.
- Failures after CAS commit are **HOLD**: owner approval can be consumed before the file is published. A partial pending file MUST NOT be silently removed or retried. This initial stage intentionally lacks crash recovery and revocation handling.

## Falsifiers / CI
Ten actual UID0 tests using separately signed synthetic B1a package, owner and witness keys: first fixed commit, byte-for-byte hash/size/mode and exactly one CAS revision, duplicate request, pre-existing release, interrupted pending, symlink destination, forged owner signature, signed package mutation after FD pin, wrong host/challenge, missing OS enrollment and expired signed artifact. Tests are serialized because the constant disposable root namespace is a shared resource. CI explicitly proves the path is absent before and after all tests.

## Explicit nonclaims
The package fixture is signed but not a real executable ELF. A separate B1b2b QEMU test already proves that a valid signed **real** Node runs under nonprivileged systemd and survives reboot/forced QEMU death; B1c0 has not connected this CAS-gated fixed transaction to that guest yet. This stage does not give install authority to a socket, prove hostile-root/snapshot rollback safety, implement owner UI confirmation or revocation, test power loss at all fsync boundaries, or guarantee automatic recovery after a consumed approval. It uses fixture time and does not claim a secure production clock. It must never be deployed as a production installer.

**Next acceptance gate:** use the existing QEMU guest to run the fixed-path transaction with an actual ELF and then start exactly one nonprivileged Node service, proving interrupted commit recovery, reapproval/revocation, correct rollback, and no changes outside the disposable VM.
