# VIDEO-18c-02b-02b-02b — различные подписанные установленные поколения (NON-RELEASE)

**Назначение:** закрыть ограничение #1010, когда историческая и новая Akula были действительно разными исходно собранными EXE, но старый EXE запускался отдельно, а установленные legacy/current совпадали побайтно.

## Приёмка на одноразовом GitHub-hosted Windows PR runner

1. Исторический Akula PE берётся из фиксированного исходного коммита ec6d6d48a78e60fca7a6f810b825418500bad64b; кандидат — из точного HEAD PR. Оба собраны отдельно через Cargo --release --locked. Проверяются реальные PE/MZ, SHA-256 и различие old/new Akula.
2. Через два настоящих NSIS создаются защищённые legacy flat и current/ под случайным путём Program Files. **Каждое поколение имеет пять настоящих PE.** Akula GUI отличается, четыре вспомогательных PE могут иметь одинаковые SHA: это не пять независимо обновлённых программ.
3. Для старого и нового установленных наборов строятся **два отдельных манифеста**, подписанных временным Minisign 0.12; подпись каждого и ошибочная перекрёстная подпись проверяются. Сведения о коммитах и Cargo.lock включены в манифесты. Никаких ключей издателя и бинарных артефактов релиза.
4. Запускается исторический GUI **из защищённой установки**, доказывается видимое окно и фактический PID. При умышленном повреждении current/ отклоняется неполная новая генерация, а старая остаётся целой.
5. Для нового current/ прежняя криптографическая цепочка SignedFive проверяет пять SHA-256, подписанный manifest digest, реальный first-presented-frame ACK, неверный nonce и неверное поколение.
6. Выполняется штатный dual-layout uninstall; независимый пользовательский файл не меняется. Никакой активации rar2 и подтверждения обновления.

## Ограничения

Обе исходные Cargo.toml версии фактически **0.3.20**. Метка **0.3.21** в новом лабораторном подписанном манифесте не доказывает повышение версии самого продукта. Старый манифест имеет 0.3.20, и только новый проходит тестовый SignedFive кандидатный допуск. Подпись старого манифеста проверяется Minisign и точными SHA, а не полноценной промышленной цепью доверия. Отдельная проверка не доказывает реальное атомарное переключение активной установки через rar2, positive ACK→confirm или продуктовый updater.

**VIDEO-18 RELEASE HOLD:** релиз, издательские ключи, пользовательские установки, обновления и публикация отключены. Следующий этап — 02b-03: реальный rar2 positive candidate activation, проверка ACK и confirm, отрицательные сценарии с откатом всех пяти PE.
