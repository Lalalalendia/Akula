# VIDEO-18b-18c-01 — первый кадр GUI: экспериментальная Windows-транспортная квитанция

**NON-RELEASE / эксперимент VIDEO UI; никаких подтверждений реальных обновлений.**

## Выявленное ограничение

В Akula уже есть корректная точка вызова `Host::redraw`: только после успешного `renderer.draw`, ненулевого списка повреждённых областей, возврата из `output.present(&drawn)` и `self.reveal()`. Linux/macOS installed-режимы используют эту точку для наблюдаемого подтверждения первого кадра. На Windows она **не подключена**. Ранее принятые #995–1001 доказали защищённую пяти-PE установку и откат без ACK, но не доказывают получение ACK от запущенного нового GUI.

## Что реализовано

1. Выделен маленький `updater/frame_ack.rs`: сохраняет существующий установленный Linux/macOS маршрут, а Windows-обработчик включает **только** при сочетании `target_os=windows`, `installed`, `video-rust-bundle`, `video-ui-e2e`. Обычный двухкомпонентный Windows updater остаётся без изменений, не создаёт ACK.
2. `host/frame.rs` включает этот экспериментальный Windows обработчик из **того же места**, сразу после `output.present` и `reveal` и только для `!drawn.is_empty()`. События `process started`, `media decoded`, `hover`, `click`, пустые перерисовки и невидимое окно не должны становиться источником ACK.
3. `updater/windows_first_gui_ack.rs` принимает только полный комплект переменных дочернего процесса: **унаследованный** HANDLE анонимного Win32 pipe, 32 lowercase hex nonce, 64 lowercase hex `generation_sha256`, строгую тройную версию и PID контроллера. При отсутствии всего комплекта — бездействие; при частичном/ошибочном — отказ. Это **не** доверие к тексту окружения как к издательской подписи.
4. Отправитель проверяет через OS `GetFileType` и `GetHandleInformation`, что HANDLE — настоящая унаследованная труба, а не обычный файл. Через `WriteFile` отправляется ограниченная 256 байтами запись `AKULA-WIN-FIRST-PRESENTED-V1\tNONCE\tVERSION\tGENERATION_SHA256\tGUI_PID\n`. Один процесс делает не более одной попытки; отправка происходит в отдельном thread, не блокируя окно.
5. Windows unit tests реально создают анонимную пару `CreatePipe`, доказывают отказ неунаследованной трубе, затем успешный OS `WriteFile/ReadFile` и точный формат. Парсер отклоняет неполные/нечисловые HANDLE и PID, неканоническую версию, неправильные nonce/sha и совпадающий PID. Source/negative tests проверяют положение hook относительно `present/reveal`, запрет пустой перерисовки, проверку HANDLE и release isolation.
6. Вместо новой глобальной CI-линии в существующем **VIDEO-18b-14 Windows real-GUI** workflow запускается дополнительный `cargo test --release ...` для Windows отправителя, после чего старый физический Download → restart → Play GUI E2E должен остаться успешным. Новый PR запускает этот workflow по двум новым модулям и собственному source/negative контракту.

## Ключевое ограничение

Это только **GUI-side sender** и его реальный Windows pipe-unit test. В этом PR нет реального доверенного updater-контроллера, создающего канал и запускающего именно новую установленную Akula; **нет** доказательства end-to-end квитанции от живого GUI новой версии. Полученный текст внутри дочернего процесса не является авторизацией: будущий контроллер обязан независимо проверить actual Child PID/process handle, защищённый путь, подписанный пяти-PE manifest, точную версию и generation digest, ownership OS lock, bounded deadline, успешный frame witness и однократность. Без этого **не вызывать** `confirm_candidate`.

Этот emitter намеренно не принимает решения об обновлениях и не вызывает ни `apply`, ни `confirm`, не открывает сеть/файлы, не удаляет старую версию и не меняет выпускную конфигурацию. Сам вызов `output.present()` может не гарантировать факт физического отображения на мониторе при сбое драйвера; приёмка end-to-end должна дополнительно удостоверять настоящий GUI-frame (снимок/OS compositor evidence).

## Следующий блок P0

Отдельный trusted Windows controller создаёт приватный inherited pipe и запускает **подписанную** новую Akula из проверенного `current/`, сохраняет собственный процесс вне обновляемой директории и удерживает OS lock; контроллер сопоставляет exact PID+token, nonce, подписанный manifest SHA, срок, фактически представленный frame. Для ложного, повторного, чужого, запоздалого или отсутствующего ACK — rollback всех пяти старых PE. Проверки kill/restart, аппаратный power-cut/AV, Win10/Win11 необходимы до снятия **VIDEO-18 PUBLIC RELEASE HOLD**.
