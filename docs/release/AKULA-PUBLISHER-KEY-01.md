# RELEASE-AKULA-OWNER-KEY-01 — Akula publisher root prepared, updates still HOLD

Owner-provided public key format verified: the pasted 152-character string is base64 of a **two-line Minisign public-key document**; it is *not* the private key and not the raw 32-byte Ed25519 key. After decoding, the key identifies as **D7A66B6D4046F6C5**, with a 42-byte Minisign `Ed` key record. The public key is pinned as the exact base64 text in `aquilum-app/native/src/updater/release.rs` so the existing `release::verify()` routine continues to use its expected format.

## Security separation

- `PUBLIC_KEY` is **public**; it can be checked into Git. Neither the private signing key nor its password may be checked in, sent through ChatGPT, or stored in Notion.
- `channel_ready()` remains **false** and Akula's existing `updater::available()` remains false. The inherited direct Windows `apply(Vec<u8>)` path is not release-authorized by merely pinning the key.
- The old Aquilum publisher key is never accepted. The old release workflow remains an immutable fail-closed HOLD. No GitHub Releases are published or modified by this PR.
- Unit tests decode the pinned Minisign document using the same Rust crate as the updater, reject unintended key ID changes, and assert the update channel remains disabled. The GitHub release-isolation policy independently decodes and pins the same key ID.

## One-time owner setup (not a step the assistant can perform)

Create environment [Akula repository → Settings → Environments](https://github.com/Lalalalendia/Akula/settings/environments) named **`akula-release`**. Protect it with the `main` branch restriction and an appropriate reviewer approval. Add two **Environment secrets**:

| Secret | Value |
|---|---|
| `CARGO_PACKAGER_SIGN_PRIVATE_KEY` | The complete private key content generated by cargo-packager 0.11.8 |
| `CARGO_PACKAGER_SIGN_PRIVATE_KEY_PASSWORD` | The key's signing password |

Do **not** use repository-wide secrets or pass these values into PR workflows. Keep another offline backup of the encrypted private key and its password in separate trusted storage.

## Prove that the owner can sign without publishing a release

After merging this PR and configuring the protected environment, manually run [Actions → Akula publisher key proof (no release)](https://github.com/Lalalalendia/Akula/actions/workflows/akula-publisher-key-proof.yml) on **main**.

The workflow:

1. Checks the immutable checked-out main SHA and verifies the exact pinned public key ID.
2. Loads secrets **only in a protected, main-only manual job**; never from pull requests or forks.
3. Signs a one-time challenge using pinned `cargo-packager 0.11.8`.
4. Verifies the resulting signature with the checked-in Akula public key using an independent `minisign` CLI.
5. Alters the challenge and requires that verification fails.
6. Emits `AKULA_PUBLISHER_OWNER_KEY_PASS key_id=D7A66B6D4046F6C5 signed_challenge=1 tamper_refused=1 no_release=1` only on success.

It writes **no GitHub Release** and grants `contents: read` only. If the environment or secrets are absent, the run fails rather than treating an unsigned package as approved.

## Build and verify a real Windows release candidate (without public publication)

After the key proof passes, manually trigger [Actions → Akula Windows signed candidate (review only)](https://github.com/Lalalalendia/Akula/actions/workflows/akula-windows-signed-candidate.yml) on `main`.

- The **main-only, environment-protected** Windows runner compiles the real native Akula package and builds the actual NSIS installer at pinned `github.sha`.
- It runs the existing real Windows install/GUI/edit/reopen/uninstall smoke before touching the key secret.
- It signs the exact tested `Akula_{version}_x64-setup.exe` bytes with the owner private key.
- It creates `latest.json` binding product, version, source commit, Cargo.lock SHA-256, installer URL, signature, file size and SHA-256, and signs that exact metadata file.
- An **independent Ubuntu verifier without any private key** downloads the candidate, rechecks source/platform/package metadata, verifies both detached signatures against the pinned public key, and proves tampered metadata cannot verify.
- Output is a temporary GitHub Actions artifact named `akula-windows-signed-stage-NOT-RELEASE`; there is no automatic release, uploader token or write permission. The approval gate is `AKULA_WINDOWS_SIGNED_CANDIDATE_PASS real_installer=1 signed_manifest=1 independent_verify=1 tamper_refused=1 no_release=1`.

**Important:** This creates a verified, signed candidate for owner review. It does not make the updater accessible to installed Windows clients. That still requires actual release publication, the signed-manifest-aware client, and a verified in-app update/rollback scenario.
