# VIDEO-18b-15 — проверка применимости существующего rar2 UpdateEngine к пяти EXE Akula

**NON-RELEASE / LAB.** Код обновления пользовательского приложения, установленная Akula, подписанные релизы, VPS и пользовательские файлы не изменяются.

## Почему этот этап нужен

Автономный эксперимент VIDEO-18b-13 (#995) уже доказал восстановление пятикомпонентной генерации после аварийного выхода процесса. Но он не интегрирован с действующим Windows updater. Релизный план Akula требует не создавать ещё один несовместимый механизм транзакций, а повторно использовать существующий Rust-код из `Lalalalendia/rar2`.

Проверяем точный upstream commit: `Lalalalendia/rar2@32a803e67244836d2794f9bbbdf9b24deab63d7e`. У этого исходного коммита **нет корневого Cargo.lock**. Для одноразового исследовательского CI создаётся временный lock в изолированном checkout, фиксируется его SHA-256 и только после этого тест выполняется с `--locked`. Это **не** доказательство фиксированного графа зависимостей для выпуска; перед реальной интеграцией нужен отдельный reviewed lock.

## Что проверяет этот PR

1. На одноразовом Windows 2022 runner GitHub Actions загружает строго указанный SHA `rar2` и копирует только тестовый адаптер Akula в его `chaptera-update-engine/tests`; upstream engine остаётся неизменённым.
2. Адаптер требует пять имён `akula-app.exe`, `shiva-pdf-preview.exe`, `akula-video-mux.exe`, `akula-yt-dlp.exe`, `akula-quickjs.exe`. Посторонние или отсутствующие файлы отклоняются до записи журнала.
3. Через реальные `UpdateEngine` API проводятся состояния `Prepared`, `PreviousRetained`, `CandidateActivated`. Без подтверждения возвращаются все **пять** предыдущих файлов; тестовая заметка вне install tree не меняется.
4. Отдельный только тестовый `confirm_candidate` проверяет сохранение всех пяти файлов новой генерации, **не изображая** получение настоящего подписанного и привязанного к генерации GUI ACK.
5. Проверяется, что текущий плоский пяти-EXE NSIS layout нельзя молча считать совместимым с `rar2` `current/.staging/.rollback`. Нужен отдельно проверенный мост или миграция установки.
6. Отрицательные Node tests запрещают переход на движущуюся ветку upstream, потерю триггеров source или появление релизной публикации.

## Что остаётся перед настоящим обновлением

- Подписанная Akula-специфичная пятифайловая идентичность, проверка точных PE-байт, источник и версия.
- Защищённый install layout и его совместимость с NSIS; привилегированный отдельный подписанный контроллер, блокировка и восстановление.
- Полная проверка first **presented** GUI frame ACK, связанного с версией и пятью SHA.
- Обрывы процесса, перезагрузка, locked-file/AV и проверка на реальном Windows 10/11.
- Публичный выпуск остаётся HOLD. Проект по лицензиям не входит в эту инженерную очередь.

**Ограничение:** этот PR — проверка повторного использования транзакционного движка на синтетических файлах, а не готовый пятикомпонентный updater. Не объединять без точных успехов Windows CI и source/negative tests.
