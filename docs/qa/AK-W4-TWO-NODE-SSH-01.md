# AK-W4-TWO-NODE-SSH-01 — испытание Akula между ПК и VPS

**Цель:** проверить реальную доставку тестового письма между двумя независимыми Linux-системами через исходящее SSH-соединение, не открывая порт приложения в Интернет.

Реализация W3/W4 включена в основную ветку Akula после [PR №679](https://github.com/Lalalalendia/Akula/pull/679), но обычная сборка по-прежнему не включает испытательную функцию. Используйте **специальный Linux x86_64 AppImage**, уже прошедший проверки.

## Необходимое

- Домашний ПК с Linux x86_64 и независимый VPS с Linux x86_64, доступный по SSH под **обычной, не root** учётной записью.
- На ПК: `ssh`, `scp`, `sha256sum`, `timeout`, `bash`. На VPS: `timeout`, `mktemp`, `sha256sum`.
- Заранее **проверенный отпечаток SSH-ключа сервера** в `~/.ssh/known_hosts`. Автоматическое принятие неизвестного ключа запрещено. Для испытаний должен быть настроен вход по ключу без запроса пароля.
- [Испытательный ZIP с Akula 0.3.13 и W3/W4](https://github.com/Lalalalendia/Akula/actions/runs/40022244044/artifacts/12531172018) и закреплённый SHA-256 AppImage: `0b99bb12823e7ff697747951611f252c2f726a43deff4f1f4cde9b181f9d7414`.
- Сам проверяемый сценарий [`scripts/qa/w4-two-node-ssh.sh`](../../scripts/qa/w4-two-node-ssh.sh) из репозитория Akula. На VPS заранее скачивать Akula **не требуется**: сценарий переносит только копию публичного испытательного AppImage.

## Запуск с одного ПК

Распакуйте ZIP, проверьте контрольную сумму. Выполните из корня репозитория Akula:

```bash
unzip akula-w4-installed-canary.zip -d akula-test
cd akula-test
sha256sum -c APPIMAGE_SHA256.txt
chmod +x akula-app_0.3.13_x86_64.AppImage
cd ..
APP="$(realpath akula-test/akula-app_0.3.13_x86_64.AppImage)"
SHA="0b99bb12823e7ff697747951611f252c2f726a43deff4f1f4cde9b181f9d7414"

# Сначала: проверить обе системы, SSH и исполняемый файл.
bash scripts/qa/w4-two-node-ssh.sh --preflight "$APP" operator@your-vps.example "$SHA"

# Затем: запуск полного испытания с отчётом.
bash scripts/qa/w4-two-node-ssh.sh "$APP" operator@your-vps.example "$SHA" w4-two-node-result.txt
```

**При этом сценарий:**
1. Проверяет SHA-256 AppImage на ПК и отдельно на VPS, его встроенную проверку WOW, Linux x86_64 и два **разных** идентификатора машин. Отказывается от запуска с `root`, `localhost`, неподтверждённым ключом SSH, изменённым файлом или повторно использованным отчётом.
2. Создаёт отдельные временные личные хранилища ключей и SQLite (права доступа 0700). Через SSH пересылает **только тестовый AppImage**; публичные идентификаторы участников извлекает локально из команд Akula. **Приватные ключи между устройствами не копируются.**
3. Открывает **один исходящий SSH-туннель** с ПК на VPS: `127.0.0.1:42043` на ПК → `127.0.0.1:42042` на VPS. На VPS не появляется публичного TCP-порта приложения.
4. Передаёт 1024 тестовых байта, проверяет сохранение W3 у получателя и настоящую подписанную W4 на отправителе.
5. Воспроизводит потерю W4 после сохранения письма и повторяет **то же** письмо. Проверяет состояние `duplicate` у получателя и отсутствие нового сохранения.
6. Выводит только обезличенные признаки результата и контрольные суммы. В отчёте нет приватных ключей, открытых приглашений или текста письма. После завершения удаляет временные испытательные каталоги на обоих узлах.

**Ожидаемая строка:** `AKULA_W4_TWO_NODE_SSH_PASS`. Поля `lost_w4=1`, `duplicate_commits=0`, `recipient_signed_w4=verified` подтверждают три ключевых свойства.

Если проверка прервётся, результат нельзя считать успешным; пользовательские заметки Akula не изменяются. Для диагностики остаются сообщения об этапах, но секреты теста по умолчанию очищаются.

## Что именно доказывает

Две **разные установки Linux** и реальное SSH-соединение по сети. Сравнение `/etc/machine-id` исключает тривиальную ошибку «два пользователя на одном Linux-хосте», но **не является доказательством двух физических компьютеров**: VPS обычно виртуальный. Если ПК и VPS находятся в одной сети, сценарий также не удостоверяет прохождение именно публичного Интернета.

Это **не проверка** Roha/noq/UDP, Direct4/Parallel4/K4, сети кастодианов, полноценной переписки произвольными текстами или нативных клиентов Windows 7/10. Карточку Notion «Два физических ПК» оставлять **НЕТ**, пока не пройдут буквально два физических ПК.

## Важные границы

- Никаких новых общедоступных портов, `sudo`, изменения постоянных настроек SSH-сервера, постоянного хранения ключей или производственных сообщений.
- Исходный AppImage пока неподписан как массовый выпуск: его SHA-256 доказывает совпадение с выбранной сборкой GitHub, а не доверие к неизвестному издателю.
- На VPS и ПК должен быть предварительно установлен доверенный SSH-ключ; не обходите `StrictHostKeyChecking=yes`.
- В случае обрыва сети процесс получателя ограничен системным `timeout`; приватные временные каталоги обычно очищаются, но если VPS недоступен при очистке, путь вида `/tmp/akula-w4-remote.*` нужно проверить вручную **после восстановления SSH**.
- Отчёт прикладывать к [E2E-01 в Notion](https://app.notion.com/p/40032a84beec81349bafc1ecd765dd58) только после фактического запуска на двух машинах. Сам факт наличия сценария или прохода имитации SSH в GitHub Actions **не является** сетевой приёмкой.
