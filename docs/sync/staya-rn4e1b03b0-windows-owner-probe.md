# RN-4E1b-03b0 — Windows installer-owned host namespace negative check (P0 lab)

**Why:** [PR #433](https://github.com/Lalalalendia/Akula/pull/433) proved that two syntactically valid SQLite host registries can produce the same read-only result. A user-created registry or JSON/BLAKE3 witness is **not** an authorization source. Existing `filegate_windows_acl::audit_owner_dacl` intentionally allows the desktop user, so it cannot establish *installer-owned* P2P authority.

**Experiment:** opt-in default-OFF Core feature `sync-installed-host-windows-owner-probe`. Reuse the existing read-only opened-handle NT security descriptor code with a **stricter owner and write ACL policy**: only SYSTEM or BUILTIN Administrators may own the host DB, its independently rooted witness, and their directory ancestor chains; only SYSTEM or Administrators may have recognized namespace-write allow ACEs. Missing/null DACL, unknown ACE, untrusted owner or writable user-owned ancestor refuses. Every directory uses an independently opened pinned `PinnedProbeRoot`, and each regular file is opened read-only without following an alias.

**No trust escalation:** returns only `Result<(), HostCustodyError>`, not any P2P capability. It is not called by ordinary Core or installed Akula and never updates registry ACLs, grants, or user files. Existing per-user File Gate ACL audit remains unchanged in behavior. This is **not** a complete impersonation/effective-access calculation; inherited/deny ACE complexities, elevated hostile admins, full descendant namespace immutability, authenticated installer creation and an actual privileged OS Broker IPC remain open.

**CI:** pinned Windows runner, compiler/Rustfmt/Cargo.lock and negative tests proving unprivileged temporary DB+witness, missing files, same-directory witness, and relative paths refuse before a real privileged source is present. Linux is unaffected; this project still requires **independent, positive, OS-verified installer-issued fixtures and lifecycle tests** before productive use.

**Next RN-4E1b-03b1:** design and implement a real privileged broker-owned immutable host registration/epoch and authenticated narrow IPC. The broker must independently authorize one registered P2P local replica (not an S3 profile), include local root identity, VaultId, DeviceId, actual QUIC EndpointId, issuer, object scope, and monotonic grant epoch, and deny if the installed trust anchor is unavailable. No File Gate writer, Bao, `APPLIED` or ACK is activated in this negative preflight. STY-G2-06 remains HOLD.
