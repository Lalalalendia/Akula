# LANG-02 — коллекции: read-only формирование общего учебного набора

**Стадия:** in PR (draft). Только Core-алгоритм; никакой GUI, плагинного runtime или записи в хранилище.

## Цель
Именованные коллекции могут ссылаться на множество таблиц в разных заметках и хранилищах. Одна таблица включается в несколько коллекций. В коллекциях хранятся только ID таблиц и настройки ролей столбцов — не копии слов или переводов.

## Контракты
- `learning::collections::Registry` хранит коллекции и одну настройку колонок на таблицу.
- `assemble` принимает выбранные коллекции и только актуальные распарсенные снимки таблиц, предоставленные доверенным вызывающим кодом. Не читает файлов и не предоставляет разрешения.
- Объединение коллекций идемпотентно: несколько ссылок на один источник дают ровно один источник в наборе.
- Отсутствующие/недоступные таблицы остаются в membership и попадают в список `unavailable` без содержимого.
- Повторяющиеся снимки одного источника, некорректные ID, дубли настроек и несовместимые колонки считаются ошибкой, а не выбираются произвольно.
- Задания опираются на актуальные значения текущих снимков. Изменение значения в таблице автоматически видно при следующем построении набора.
- Пределы `max_tables`, `max_rows_per_table` обязательны. Значение `source_row` в выдаче временное и не подходит для сохранения истории ответов.

## Оставшиеся зависимости
- Доверенная выдача стабильных `vault/note/table` ID, sidecar persistence и проверка пересопоставления после правок.
- Связь с текущим unsaved `DocumentHub` snapshot, grant validation в UI/host и File Gate для возможных операций записи.
- Редакторская команда подключения таблицы, список коллекций, фильтры и пользовательские E2E.
