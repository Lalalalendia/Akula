# AK-W4-PROD-CANARY-01: встроенная переписка Akula — опытный выпуск

Дата: 23.10.2026. Источник: [WOW PR #81](https://github.com/calex794/wow/pull/81), [Akula E2E-01](https://app.notion.com/p/40032a84beec81349bafc1ecd765dd58).

## Что действительно включено

Главный исполняемый файл Akula принимает команду --w4-pilot только в специальной сборке Linux. Это код **основной программы**, а не отдельный несвязанный продукт. Подписанный W3/W4 выполняет второй исполняемый файл, который собирается отдельно из закреплённого SHA WOW 85b95c1d38a9a8b803b5e0ba1d9fcaac521e4dfa. Его точная SHA-256 записывается в Akula при сборке и проверяется при каждом запуске.

Это предотвращает конфликт SQLite между WOW и ядром заметок Akula. Во время обычного запуска Akula W4 не слушает сеть, не читает Vault и не обращается к неизвестным узлам. Отдельная команда пользователя обязательна.

Реализованы: W3 v3 с подлинной подписью и шифрованием, независимые SQLite отправителя и получателя, подписанная Ed25519 W4 только после фиксации, закрытая обратная HPKE-квитанция, сохранение точного зашифрованного W3 и повтор при потере W4. Соединение только на 127.0.0.1, связь по Интернету — через вручную включённый доверенный SSH-канал.

## Команды испытательной версии

- akula-app --w4-pilot status — проверить помощник и его хэш, ничего не отправляя.
- akula-app --w4-pilot init-sender — однократно создать приватную личность отправителя, показать открытый SENDER_VERIFY.
- akula-app --w4-pilot init-recipient — однократно создать ключи получателя, показать публичное RECIPIENT_INVITE.
- akula-app --w4-pilot listen SENDER_VERIFY — однократно принять W3 от заранее сверенного отправителя на 127.0.0.1:42042.
- akula-app --w4-pilot listen-drop-ack SENDER_VERIFY — внедрить потерю W4 после коммита получателя.
- akula-app --w4-pilot send-test RECIPIENT_INVITE — отправить строго 1024 тестовых байта на 127.0.0.1:42043.
- akula-app --w4-pilot resend RECIPIENT_INVITE MESSAGE_ID — повторить **те же** байты W3 из локальной SQLite после обрыва ответного канала.

Секреты отдельно от заметок: домашний каталог приложения Akula, подкаталог messaging-w4-pilot-v1 (Unix права каталога 0700, секретных ключей 0600). Не копировать секретные файлы между устройствами. При широких правах или подмене исполняемого файла — отказ. Для аварийного выключения: AKULA_DISABLE_W4_PILOT=1.

## Проверка загруженного AppImage

В ZIP из GitHub Actions содержатся `akula-app_0.3.13_x86_64.AppImage`, `APPIMAGE_SHA256.txt` и каталог `docs`. После распаковки ZIP:

```bash
sha256sum -c APPIMAGE_SHA256.txt
chmod +x akula-app_0.3.13_x86_64.AppImage
./akula-app_0.3.13_x86_64.AppImage --appimage-extract >/dev/null
(cd squashfs-root && sha256sum -c ../docs/W4_HELPER_SHA256.txt)
APPIMAGE_EXTRACT_AND_RUN=1 ./akula-app_0.3.13_x86_64.AppImage --w4-pilot status
```

Ожидается `OK` для обеих контрольных сумм и строка `AKULA_W4_PILOT_READY`. При ошибке хотя бы одной проверки **не запускайте испытание**. Контрольные суммы подтверждают совпадение с GitHub-артефактом, но сами по себе не заменяют проверку доверия к выпуску и исходному коду.

Для первого опыта используйте **только проверенный испытательный файл и тестовые письма**. Приложение не получает разрешения менять заметки, хранилища или слушать публичные порты.

## Первый опыт PC + VPS

Получатель (Linux VPS), отдельный терминал:
1. akula-app --w4-pilot init-recipient
2. Передать только значение RECIPIENT_INVITE своему отправителю по заранее проверенному каналу.
3. akula-app --w4-pilot listen SENDER_VERIFY_ОТ_ОТПРАВИТЕЛЯ

Отправитель (другой Linux PC):
1. akula-app --w4-pilot init-sender
2. Передать только SENDER_VERIFY получателю; проверить личность независимо.
3. В отдельном терминале открыть SSH со строгой проверкой ключа хоста:
   ssh -N -T -o BatchMode=yes -o StrictHostKeyChecking=yes -o ExitOnForwardFailure=yes -L 127.0.0.1:42043:127.0.0.1:42042 operator@trusted-vps
4. akula-app --w4-pilot send-test RECIPIENT_INVITE_ОТ_ПОЛУЧАТЕЛЯ

Ожидается RECIPIENT_COMMITTED на VPS и RECIPIENT_CONFIRMED на отправителе. Повторить с listen-drop-ack, сохранить MESSAGE_ID, затем запустить listen и resend. До реальной подписанной W4 состояние отправителя должно оставаться Queued.

## Границы безопасности и испытаний

- Пока только Linux x86_64; Windows 7/10 требуют отдельного системного защищённого хранилища ключей. Опыт в WSL2 не считается нативной Windows-проверкой.
- Лимит передач в этом испытании K=1. Direct4, Parallel4, K4, криптографический W8 и независимые кастодианы остаются научной и отдельной прикладной работой. Они не становятся работающим функционалом редактора от одного подключения W4.
- Нет разрешения от удалённого источника на редактирование Vault, нет синхронизации файлов и общей выдачи доступа. Публичные TCP/UDP-порты приложения не открываются.
- Это ограниченный **инструмент для работы в основной Akula** с явным вызовом, ещё не полноценный интерфейс чата; стандартная Windows-версия Akula остаётся без этой функции.
- Основной release workflow в Akula сознательно HOLD; эта работа готовит только отдельный тестовый AppImage, не подменяет издательскую подпись, правила обновления или отката.
