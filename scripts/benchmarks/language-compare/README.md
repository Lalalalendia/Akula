# Language comparison — one-shot, isolated research

This is not an Akula production benchmark and no language wins by default.
The experiment compares the same two algorithms on the SAME Linux x86-64 runner:

1. Exact sieve of Eratosthenes, integers 2..10,000,000, byte-sized flags when possible: expected count 664579.
2. Unsigned, wrapping rolling hash over 20,000,000 generated bytes: expected 1936361925. Each hash iteration depends on the preceding value.

All programs print two decimal numbers. Wrong output or unavailable compilers are excluded, not assigned a slow time. Every build is optimized for speed; every correct program has one correctness preflight and five interleaved timed executions. GitHub artifact contains summary.md, results.json, results.csv, and build logs.

Candidates: C, C++, Rust, Zig, Odin, C3, D (GDC), Nim, Go, Fortran, Free Pascal, and Python as a high-level interpreter control. The compiler setup uses official Ubuntu packages and pinned release links for Zig 0.17, Odin dev-2026-10 and C3 0.8.5. Zig archive SHA256 is checked; Odin/C3 archive hashes are recorded, not independently pinned. Toolchain downloads are excluded from build times.

Local use: python3 run.py --output .language-compare --repetitions 5

This workflow runs only on branch research/language-compare-20261025 when the benchmark files are changed. It does not touch required application checks and it never auto-merges.

Limitations: single shared CI host, five short samples, two narrow algorithms timed together, language-specific runtimes, different bounds checking, compiler backends, build flags, and executable startup costs. This does not prove that one language is universally faster than another. Full evaluation should separate workloads and use real Akula tasks, multiple operating systems and repeated controlled measurements.
